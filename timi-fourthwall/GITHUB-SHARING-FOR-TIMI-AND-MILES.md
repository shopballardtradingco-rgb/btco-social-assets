# GitHub sharing, explained simply — for Timi and Miles

**Purpose:** Fewer messages to Tim, fewer lost decisions, and one reliable place to find the latest approved project information.

## Timi: What is GitHub?

Imagine a **shared project binder with a built-in time machine**.

- **Git** keeps track of changes, like a record of what a document said yesterday and what changed today.
- **GitHub** is the online shelf where we keep that organized binder and give people links to the latest approved version.
- Instead of asking Tim to resend a plan, you or Miles open its link. Everyone can see the same version, and older versions are traceable.

You do **not** need to learn to code or edit GitHub. It should save you work, not give you another chore.

**Important distinction:** The approved, shareable instructions live on GitHub; **ideas, draft designs, questions, and feedback go into our shared ChatGPT discussion first**. GitHub is not a place where you're expected to submit files. Tim and Athena handle authorized updates.

## Your roles

- **Timi:** Owns her creative vision, artwork, design choices, and approval of changes to her own shop. She can say no or change direction.
- **Miles:** Her AI assistant. Reads the latest approved documents, helps make simple options, gathers feedback, and prepares a clear handoff.
- **Tim:** Founder and final architect/approver for Ballard AI Studio's systems, integration, access, GitHub publishing, and technical changes.
- **Athena:** Coordinates and makes authorized updates on the owner side only, with verifiable links.

Nobody gets to overrule Timi about her own creative work. Nobody gets to change the shared system without Tim's authorization.

## The five-step routine

1. **Start with the current binder.** Miles reads [Timi's Fourthwall README](README.md) and the relevant linked documents. Older chats are context, not proof of the latest decision.
2. **Work normally with Timi.** Brainstorm, sketch, decide. Miles keeps explanations short and offers one or two choices at a time. Don't add GitHub chores.
3. **Get the right approval.** Timi approves her design or shop choice. If an update also changes shared system rules, access, publishing, spending, or architecture, Tim makes the final system decision. Neither approval automatically grants GitHub write access.
4. **Share a compact handoff in the shared ChatGPT Project** (or another agreed private discussion channel). Include what changed, whose approval exists, which document should change, and the relevant file or image. This replaces repeatedly forwarding bits of conversation to Tim. Until the shared space is available, prepare a single copy-and-paste handoff rather than sending many messages.
5. **Check the published link.** Tim/Athena review and, where authorized, publish the update. Miles reopens the document and verifies it changed before treating it as current.

## Miles: Permanent operating instructions

> You are Miles, Timi's AI partner in Ballard AI Studio. **Your GitHub access is strictly read-only.** Never create, edit, or delete GitHub files, commits, issues, issue comments, pull requests, releases, settings, workflows, or deployments. Never use another person's login, a token, a browser, an automation, or a third-party service to bypass that restriction. Never ask Timi to push changes for you.
>
> Begin each project by checking the approved GitHub README and relevant linked material. Explain GitHub to Timi as a shared project binder with version history, not a coding job.
>
> Timi controls her creative decisions and her shop. Tim retains final system architecture, technical permission, publishing, and governance approval. Gather feedback respectfully, and distinguish ideas, drafts, approvals, and changes actually verified.
>
> For each meaningful update, produce **one short handoff** for the shared ChatGPT Project with: project; what Timi approved; what changed; suggested document(s) to update; any decision needed from Tim; source assets or links; and whether the repository update is **NOT YET PUBLISHED**. Athena/Tim handle any authorized GitHub changes.
>
> Do not claim GitHub has synced or that a document is live unless you reopen the link and verify the change. If you cannot access the shared ChatGPT Project, give Timi one paste-ready handoff instead of asking her to repeat everything.
>
> Keep private customer data, addresses, credentials, banking/tax details, and unapproved private creative assets out of public GitHub. No paid tools, purchases, product launch, or public posting without the relevant owner's explicit permission.

## Simple example

**Before:** “Tim, can you find the version of the shirt plan I sent last week? Miles has a new idea too.”

**After:** Miles reads the [current shirt plan](README.md), shows Timi an updated mockup, records Timi's feedback in a short shared-chat handoff, and Athena/Tim update the published document when authorized. Everyone reopens **one link** to see the current plan.

**Bottom line:** **Discuss together → approve with the right owner → Athena/Tim publish → everybody reads the same link.** GitHub stays read-only for Timi and Miles.
